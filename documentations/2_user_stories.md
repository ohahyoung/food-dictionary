# 음식dictionary — User Stories

> 버전: v0.1 · 작성일: 2026-11-25 · 상태: 논의용 초안
> 근거: [One Pager v0.4](0_one_pager.md), [PRD v0.1](1_product_requirements_document.md)

## 1. 목적과 범위

사용자는 먹은 음식과 **소화·속 편안함, 졸림, 에너지, 배변 변화**를 기록하며 내 몸에 잘 맞는 음식을 알아가려는 개인이다. 아래 스토리는 이 목적을 실제 사용자 행동과 검증 가능한 인수 조건으로 나눈 것이다.

- **MVP 제안:** PRD의 첫 버전 필수 범위를 구체화한 스토리. 구현 완료 또는 사용자 최종 승인을 뜻하지 않는다.
- **후속 후보:** 범위 결정 전 구현에 포함하지 않는 스토리.
- 세부 입력 척도, 플랫폼, 저장·로그인 방식, 알림 여부는 PRD의 미결정 상태를 유지한다.
- ‘관찰’은 몸 상태를 느낀 시점의 기록이다. 미기록, 모르겠음, 변화 없음은 서로 다르다.
- 인수 조건은 조건 → 행동 → 기대 결과 순서로 읽는다. 모든 예시는 가상 데이터다.

## 2. 사용자 여정과 스토리 지도

| 여정 | 사용자 행동 | MVP 제안 스토리 |
| --- | --- | --- |
| 식사 남기기 | 음식 찾기·추가, 한 끼와 시각·맥락 기록 | US-01~03 |
| 몸 상태 남기기 | 필요한 영역 선택, 시간차 관찰, 독립 배변 기록 | US-04~09 |
| 돌아보기 | 하루 기록, 음식별 경험과 영역별 요약 확인 | US-10~13 |
| 기록 관리 | 잘못된 내용·연결 수정, 삭제 | US-14~16 |
| 안심하고 지속하기 | 저장·재시도, 개인 기록 보호, 간단한 입력 | US-17~19 |

## 3. 식사 기록

### US-01. 기존 음식을 찾거나 새 음식 만들기

**스토리:** 기록하는 사용자로서, 음식 이름을 검색하고 필요하면 새 항목을 만들고 싶다. 같은 음식의 경험을 한곳에 쌓기 위해서다.

**범위:** MVP 제안 · **근거:** FR-01

**인수 조건**

- 기존 음식이 있을 때 이름으로 검색하면 해당 항목을 선택해 식사에 추가할 수 있다.
- 원하는 음식이 없을 때 이름을 입력해 새 항목을 만들면 식사에 사용할 수 있다. 이름 앞뒤 공백은 제거한다.
- 같은 이름의 음식이 있으면 기존 항목을 제안한다. 비슷하지만 다른 이름은 자동 병합하지 않는다.
- 공백만 있는 음식 이름으로는 항목을 만들 수 없다.

### US-02. 한 끼와 실제 먹은 시각 남기기

**스토리:** 식사를 마친 사용자로서, 함께 먹은 음식들과 실제 먹은 시각을 기록하고 싶다. 나중에 몸 상태와 시간 관계를 확인하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-01, AC-01

**인수 조건**

- 식사 작성을 시작하면 먹은 시각은 현재로 제안되고 과거 시각으로 변경할 수 있다.
- 밥과 생선을 추가해 저장하면 하나의 식사 안에 두 음식이 표시된다.
- 음식 또는 유효한 먹은 시각이 없으면 저장되지 않고 필요한 입력을 안내한다.
- 과거 식사를 저장하면 입력한 날이 아니라 실제 먹은 날짜에 표시된다.
- 저장이 성공하면 식사 상세를 보여주고 몸 상태 추가 동작을 제공한다.

### US-03. 음식의 양과 상황을 선택적으로 남기기

**스토리:** 기록하는 사용자로서, 음식별 양과 식사 상황을 짧게 덧붙이고 싶다. 같은 음식을 먹은 날들의 맥락을 비교하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-01, PRD §3

**인수 조건**

- 음식별 양과 식사 메모를 비워도 필수값이 있으면 저장된다.
- ‘반 공기’ 등 양 메모를 입력하면 해당 음식에 연결되어 다시 보인다.
- 조리 방식이나 그날 상황을 식사 메모에 입력하면 식사 상세에서 원문을 확인할 수 있다.
- 사진이나 구조화된 재료·생활 정보 입력을 요구하지 않는다.

## 4. 몸 상태 기록

### US-04. 느낀 영역만 빠르게 기록하기

**스토리:** 몸의 변화를 느낀 사용자로서, 관찰한 영역만 선택해 남기고 싶다. 매번 모든 항목을 채우는 부담 없이 기록하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-02~03, AC-02, AC-05

**인수 조건**

- 관찰 시각은 현재로 제안되고 실제 느낀 과거 시각으로 변경할 수 있다.
- 졸림만 선택하고 응답해도 저장되며, 나머지 영역은 미기록으로 남는다.
- 영역 응답 없이 메모만 작성하면 저장 전에 최소 한 영역의 응답을 안내한다.
- ‘모르겠음’을 선택하면 명시적인 응답으로 저장한다. 미기록을 모르겠음이나 좋은 반응으로 바꾸지 않는다.
- ‘없음’, ‘보통’, ‘평소와 비슷함’을 선택하면 실제 응답으로 보존한다.

### US-05. 속 편안함과 구체적인 불편감 남기기

**스토리:** 소화 상태를 관찰하는 사용자로서, 편안했던 느낌과 불편감의 종류·정도를 남기고 싶다. 음식별로 어떤 경험이 반복되었는지 돌아보기 위해서다.

**범위:** MVP 제안 · **근거:** FR-03

**인수 조건**

- 편안함·보통·불편함·모르겠음 중 하나를 기본 응답으로 남길 수 있다.
- 더부룩함·속쓰림·복부 불편감·가스·메스꺼움을 복수 선택하고 각 항목의 정도를 선택적으로 남길 수 있다.
- 상세 증상을 선택하면 기본 응답도 받는다. 상세 입력은 필수가 아니다.
- 편안함과 불편 증상을 함께 고르면 확인 안내를 보여주며, 사용자가 수정하거나 그대로 저장할 수 있다.

### US-06. 졸림과 에너지를 따로 기록하기

**스토리:** 식후 상태를 관찰하는 사용자로서, 졸림과 에너지를 별개로 기록하고 싶다. 서로 다른 느낌이 한 평가로 뭉쳐지지 않게 하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-03, AC-02

**인수 조건**

- 졸림은 없음·약간·많이·모르겠음, 에너지는 활력 있음·평소와 비슷함·기운 없음·모르겠음으로 각각 입력할 수 있다.
- 속 편안함과 많이 졸림을 같은 시점의 관찰로 함께 저장할 수 있다.
- 졸림을 많이로 선택해도 에너지는 자동으로 기운 없음으로 채워지지 않는다.
- 두 영역 중 하나만 입력하면 다른 영역은 미기록으로 남는다.

### US-07. 식사 연결 없이 배변과 몸 상태 남기기

**스토리:** 어느 식사와 관련 있는지 알기 어려운 사용자로서, 배변이나 몸 상태를 독립적으로 기록하고 싶다. 억지로 원인을 정하지 않고 경험을 보존하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-02~03, AC-04

**인수 조건**

- 타임라인에서 몸 상태 작성을 시작하면 식사를 고르지 않아도 저장할 수 있다.
- 배변은 사건 시각과 편안함·보통·불편함·모르겠음 중 하나를 기록하고, 변의 상태와 메모를 선택적으로 남긴다.
- 배변과 다른 몸 상태의 시각이 다르면 각각 별도 관찰로 남길 수 있다.
- 독립 관찰은 해당 날짜 타임라인에 표시하고 식사 연결이 없음을 알린다. 음식별 집계에서는 제외한다.
- 배변 기록이 없는 날을 정상이나 변비로 표시하지 않는다.

### US-08. 같은 식사의 반응을 시간에 따라 추가하기

**스토리:** 식후 변화를 관찰하는 사용자로서, 같은 식사에 다른 시점의 반응을 추가하고 싶다. 시간이 지나면서 달라진 상태를 보존하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-02, AC-03

**인수 조건**

- 식사 상세에서 반응 추가를 누르면 해당 식사가 연결된 작성 화면이 열린다.
- 같은 식사에 두 시각의 관찰을 저장하면 두 기록이 모두 남고 앞선 기록을 덮어쓰지 않는다.
- 한 관찰에는 최대 한 식사를 연결한다.
- 연결된 식사보다 앞선 관찰 시각을 입력하면 저장을 막고 시각 수정 또는 연결 해제를 안내한다.
- 같은 영역을 두 번 관찰하면 요약에서 관찰 수는 2, 관찰한 식사 수는 1로 표시된다.

### US-09. 모르는 상태와 변화 없는 상태를 구분해 돌아보기

**스토리:** 지난 기록을 읽는 사용자로서, 관찰하지 않은 항목과 판단하기 어려웠던 항목을 구분하고 싶다. 빈 기록을 좋은 반응으로 오해하지 않기 위해서다.

**범위:** MVP 제안 · **근거:** FR-03, PRD §5, AC-05

**인수 조건**

- 입력하지 않은 영역은 상세에서 미기록으로 구분한다.
- 명시적으로 선택한 모르겠음과 없음·보통 등의 응답을 원래 값으로 보여준다.
- 요약에서 모르겠음은 별도 응답 건수로 표시하고 미기록은 응답 분포에서 제외한다.
- 다른 영역의 응답으로 빈 영역을 추정하거나 채우지 않는다.

## 5. 돌아보기와 비교

### US-10. 하루의 식사와 몸 상태를 시간순으로 보기

**스토리:** 기록을 돌아보는 사용자로서, 하루의 식사와 몸 상태를 같은 흐름에서 보고 싶다. 언제 먹고 언제 어떤 느낌이 있었는지 이해하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-04, AC-08, AC-10

**인수 조건**

- 날짜를 선택하면 해당 날짜의 기록이 사건 시각순으로 보이며, 같은 시각이면 생성 순서를 사용한다.
- 연결된 관찰에는 식사 이름, 먹은 시각, 식후 경과 시간이 표시된다.
- 자정 전 식사에 다음 날 관찰을 연결하면 연결은 유지하고 관찰은 다음 날에 표시한다. 시각·시간대를 반영해 경과 시간을 계산한다.
- 기록이 없는 날에는 식사 또는 몸 상태 추가 동작이 있는 빈 화면을 보여준다.
- 각 기록에서 상세, 수정, 삭제로 이동할 수 있다.

### US-11. 음식별로 원래 식사와 경험 찾기

**스토리:** 특정 음식의 경험을 돌아보는 사용자로서, 이름으로 음식을 찾아 관련 식사와 관찰을 보고 싶다. 내 몸에 맞는 음식을 이해할 근거를 직접 확인하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-05, AC-06

**인수 조건**

- 사전에서 음식 이름으로 검색하고 해당 음식 상세를 열 수 있다.
- 상세에는 그 음식이 포함된 식사와 함께 먹은 다른 음식, 연결된 관찰이 표시된다.
- 요약에서 원래 식사·관찰 상세와 메모를 열 수 있다.
- 복수 음식 식사의 반응은 ‘이 음식을 포함한 식사에서 남긴 기록’으로 표현하며 특정 음식의 효과로 단정하지 않는다.

### US-12. 영역별 요약과 기록의 양 함께 보기

**스토리:** 경험을 비교하는 사용자로서, 영역별 응답 분포와 기록 수를 함께 보고 싶다. 적은 관찰이나 반복 입력을 과대해석하지 않기 위해서다.

**범위:** MVP 제안 · **근거:** FR-05, PRD §5, AC-03, AC-06, AC-10

**인수 조건**

- 소화·졸림·에너지·배변의 응답 분포를 따로 보여주며 종합 점수나 자동 적합성 순위를 만들지 않는다.
- 해당 음식이 포함된 고유 식사 수, 영역별 관찰 수, 관찰한 고유 식사 수를 표시한다. 한 식사에 같은 음식이 중복되어도 식사 수는 1이다.
- 해당 영역의 관찰이 한 번도 없는 식사 수를 미기록 수로 표시한다. 모르겠음은 관찰로 센다.
- 연결되지 않은 관찰은 집계하지 않는다. 복수 음식의 요약 수치를 더해 전체 관찰 수로 제시하지 않는다.
- 반응이 없으면 ‘아직 반응 기록이 없어요’를 표시한다. 기록이 적어도 임의의 신뢰도 등급이나 적합성 결론을 만들지 않는다.
- 배변 요약은 기록된 사건의 상태를 보여주고 음식의 효과로 표현하지 않는다.

### US-13. 기간을 바꿔 경험 비교하기

**스토리:** 최근 경험을 확인하려는 사용자로서, 음식별 기록의 조회 기간을 바꾸고 싶다. 전체 기록과 최근 기록을 나누어 보기 위해서다.

**범위:** MVP 제안 · **근거:** FR-05, AC-10

**인수 조건**

- 전체·최근 7일·최근 30일 중 기간을 선택할 수 있다.
- 포함할 식사는 먹은 시각을 기준으로 정하고, 해당 식사에 연결된 관찰은 날짜가 넘어가도 포함한다.
- 기간을 바꾸면 식사 목록, 표본 수, 영역별 분포가 함께 갱신된다.
- 선택 기간에 기록이 없으면 적절한 빈 상태를 표시하고 다른 기간으로 변경할 수 있다.

## 6. 기록 수정과 삭제

### US-14. 잘못 입력한 내용과 연결 수정하기

**스토리:** 기록을 보완하는 사용자로서, 식사·관찰의 내용과 시각, 관찰에 연결한 식사를 고치고 싶다. 잘못된 기록이 비교 결과에 남지 않게 하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-06, AC-07

**인수 조건**

- 식사에 잘못 선택한 음식, 양, 메모와 먹은 시각을 수정할 수 있다. 음식 항목 전체의 이름 변경·병합은 제공하지 않는다.
- 관찰의 응답·시각·메모를 수정하거나 식사 연결을 변경·해제할 수 있다.
- 독립 관찰을 유효한 식사에 연결하면 그 식사의 음식별 요약에 반영된다. 연결을 해제하면 해당 집계에서 빠진다.
- 식사 또는 관찰 시각 변경으로 관찰이 식사보다 빨라지면 저장을 막고 시각·연결 수정을 안내한다.
- 저장 성공 후 타임라인과 요약에 최신 내용만 반영된다. 수정은 새 관찰을 중복 생성하지 않는다.

### US-15. 식사를 지워도 몸 상태 기록 보존하기

**스토리:** 잘못된 식사를 삭제하는 사용자로서, 삭제 영향을 확인하고 관찰은 남기고 싶다. 몸 상태에 대한 유효한 경험까지 잃지 않기 위해서다.

**범위:** MVP 제안 · **근거:** FR-06, AC-07

**인수 조건**

- 삭제 전에 연결된 관찰 수와 관찰이 독립 기록으로 남는다는 안내를 보여준다.
- 확인하면 식사만 삭제하고 관찰은 연결을 해제해 타임라인에 보존한다.
- 보존된 관찰은 삭제된 식사를 통해 음식별 요약에 더 이상 포함되지 않는다.
- 삭제를 취소하면 식사와 연결이 그대로 유지된다.

### US-16. 불필요한 관찰만 삭제하기

**스토리:** 기록을 정리하는 사용자로서, 잘못 남긴 관찰 하나만 지우고 싶다. 식사와 다른 관찰은 유지하기 위해서다.

**범위:** MVP 제안 · **근거:** FR-06, AC-07

**인수 조건**

- 관찰 삭제 시 확인을 받고, 취소하면 아무 변화가 없다.
- 삭제를 확인하면 선택한 관찰만 제거한다. 연결된 식사와 다른 관찰은 유지한다.
- 타임라인과 영역별 응답 분포·관찰 수·관찰한 식사 수를 다시 반영한다.

## 7. 지속 사용을 위한 공통 경험

### US-17. 저장 상태를 알고 실패 후 다시 시도하기

**스토리:** 기록하는 사용자로서, 입력이 저장됐는지 알 수 있고 실패해도 다시 시도하고 싶다. 기록을 잃거나 중복으로 남기지 않기 위해서다.

**범위:** MVP 제안 · **근거:** PRD §6·§8, AC-09, AC-11

**인수 조건**

- 저장 진행 중에는 중복 제출을 막으며 완료 전에는 성공으로 표시하지 않는다.
- 저장이 실패하면 작성 화면의 입력값을 유지하고 실패 안내와 재시도를 제공한다.
- 재시도 또는 반복 클릭으로 같은 제출이 중복 기록되지 않는다.
- 저장 완료된 기록은 새로고침·재실행 후 다시 볼 수 있다. 저장 실패 상태의 재실행 복구까지 보장하는 요구는 아니다.

### US-18. 내 기록의 공개·보존 범위 알기

**스토리:** 개인 몸 상태를 남기는 사용자로서, 기록이 누구에게 보이고 어디에 보관되는지 알고 싶다. 공개 범위와 보존 한계를 이해하고 사용하기 위해서다.

**범위:** MVP 제안 · **근거:** PRD §7~8, AC-11 · **선행 결정:** 저장 방식

**인수 조건**

- 개인 기록은 기본 비공개이며 공개 링크나 검색 노출을 제공하지 않는다.
- 실제 사용 전에 선택한 저장 방식과 보존 범위를 알 수 있다.
- 서버 저장을 선택한 경우 다른 사용자의 기록 조회·수정을 차단한다.
- 기기 저장을 선택한 경우 저장 위치와 삭제·기기 변경 시 보존 범위를 안내한다.
- 검증에는 가상 기록을 사용하고, 실제 식사·몸 상태·사진을 공개 저장소·테스트 자료·분석 이벤트·오류 로그에 넣지 않는다.

### US-19. 휴대폰에서도 부담 없이 입력하기

**스토리:** 일상 중 기록하는 사용자로서, 작은 화면에서도 필요한 선택과 오류 안내를 쉽게 이해하고 싶다. 식사와 몸 상태 기록을 지속하기 위해서다.

**범위:** MVP 제안 · **근거:** PRD §8~9

**인수 조건**

- 작은 휴대폰 화면에서 핵심 입력과 기록 조회를 완료할 수 있다.
- 필드 이름, 선택 상태, 오류 원인을 텍스트로 식별할 수 있고 색상만으로 구분하지 않는다.
- 선택 입력을 채우지 않아도 필수값으로 저장할 수 있다.
- 사용성 검증에서 간단한 식사 기록은 1분 이내, 한 영역의 관찰은 30초 이내 완료를 목표로 측정한다. 이는 성능 보장이나 모든 사용자의 통과 시간을 뜻하지 않는다.

## 10. 구현 순서 제안과 완료 기준

1. **기록의 기반:** 플랫폼·저장 방식 결정 후 음식·식사 기록(US-01~03), 저장과 보호(US-17~18)를 구성한다.
2. **몸 상태와 시간 흐름:** 네 영역의 기록(US-04~09)과 하루 타임라인(US-10)을 연결한다.
3. **개인 사전과 비교:** 음식 상세·집계·기간 필터(US-11~13)를 구현한다.
4. **수정·삭제의 일관성:** US-14~16을 완성하고 전체 타임라인·집계에 반영되는지 확인한다.
5. **사용성 검증:** 전 과정에 US-19를 적용하고 PRD의 AC-01~11을 가상 기록으로 검증한다.

각 스토리는 인수 조건과 연결된 검증 시나리오를 충족하고, 관련 기록의 저장·수정·조회가 일관되게 동작할 때 완료로 판단한다. 첫 버전 출시는 MVP 제안 범위를 확정하고 모두 검증한 뒤 판단하며, 후속 후보를 자동으로 출시 조건에 포함하지 않는다.
