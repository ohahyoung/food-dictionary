## 1. 제품 목적과 확정 사항

먹은 음식과 식후 몸의 반응을 기록하고 비교하며, 소화가 잘되고 내 몸에 잘 맞는 음식을 찾아가는 **개인 음식 사전**을 만든다.

- 주 사용자는 자신의 식사와 몸 상태를 기록하고 돌아보려는 개인이다.
- 관찰 범위는 **소화·속 편안함, 졸림, 에너지, 배변 변화 모두**다.
- 핵심 가치는 음식 경험과 몸 상태의 반복되는 양상을 이해하는 데 있다.

## 2. 해결할 문제와 사용 시나리오

음식과 이후의 몸 상태는 시간이 지나면 기억하기 어렵다. 같은 음식도 양·조리 방식·함께 먹은 음식 등 기록의 맥락이 달라질 수 있으므로, 원래 경험을 다시 확인할 수 있어야 한다.

| 상황 | 사용자가 하고 싶은 일 | 기대 결과 |
| --- | --- | --- |
| 식사 직후 | 먹은 음식과 시각을 빠르게 남기기 | 식사 기록이 저장된다 |
| 시간이 지난 뒤 | 속 편안함이나 졸림 등 느낀 변화만 추가하기 | 식사 시각과 관찰 시각을 함께 볼 수 있다 |
| 다음 관찰 시점 | 같은 식사에 다른 반응을 추가하기 | 이전 반응을 덮어쓰지 않고 변화가 남는다 |
| 배변 또는 식사 연결이 불분명한 관찰 | 식사 선택 없이 몸 상태 남기기 | 하루 타임라인에 독립 기록으로 남는다 |
| 기록이 쌓인 뒤 | 특정 음식을 먹었던 날의 반응 비교하기 | 영역별 기록과 함께 먹은 음식을 확인한다 |

예시 시나리오: 점심에 밥과 생선을 기록하고, 이후 ‘속은 편안함·졸림은 많이’를 남긴다. 저녁에는 에너지 상태를 추가하고, 다음 날 배변은 독립 기록으로 남긴다. 이는 제품 동작 예시이며 실제 개인 데이터가 아니다.

## 3. 첫 버전 범위

### 필수 범위 제안

1. 음식 항목 선택·생성과 식사 기록.
2. 네 영역의 몸 상태 기록 및 식사와 선택적 연결.
3. 식사와 관찰을 시간순으로 보는 하루 타임라인.
4. 음식 검색, 음식 상세 및 영역별 기록 요약.
5. 식사·관찰 수정과 삭제.
6. 개인 기록 비공개, 저장 실패 처리, 미기록과 실제 관찰의 구분.

### 후속 검토

사진 첨부, 구조화된 재료·조리 방식·생활 맥락, 알림, 데이터 내보내기, 기기 간 동기화. 첫 버전에서는 필요한 맥락을 자유 메모로 남긴다. 로그인 필요 여부는 저장 방식과 함께 결정한다.

### 제외 범위

공개 피드, 맛집 평가, 음식 주문, 칼로리 관리, AI 음식 인식, 자동 식단 추천, 질병 진단·알레르기 판정·특정 음식의 원인 확정.

## 4. 기능 요구사항과 완료 기준

### FR-01. 음식과 식사 기록

- 사용자는 음식 이름을 검색해 기존 항목을 선택하거나 새 항목을 만든다.
- 한 끼에 하나 이상의 음식을 추가한다. 필수값은 음식과 먹은 시각이며, 시각은 현재를 기본값으로 제공하고 과거로 변경할 수 있다.
- 음식별 대략적인 양과 식사 전체 메모는 선택 입력한다. 양을 입력하지 않아도 저장된다.
- 이름 앞뒤 공백을 제거하며, 같은 이름이 있으면 기존 항목을 제안한다. 유사한 이름의 음식은 자동 병합하지 않는다.
- 저장 후 식사 상세로 이동하며 몸 상태 추가 동작을 제공한다.

**완료 기준:** 음식이 없으면 저장할 수 없다. 음식 두 개를 입력하면 하나의 식사 안에 두 항목이 보인다. 과거 식사는 입력 시각이 아닌 먹은 시각에 표시된다.

### FR-02. 몸 상태 기록

- 관찰 시각과 최소 한 영역의 응답으로 저장한다. 관찰 시각은 현재가 기본이며 과거 입력을 허용한다.
- 네 영역을 모두 작성하도록 강제하지 않는다. 응답 없이 메모만 작성한 경우 영역 선택을 안내한다.
- 식사 상세에서 시작하면 해당 식사를 연결하고, 타임라인에서 시작하면 연결 없이 작성할 수 있다.
- 한 관찰은 최대 한 식사에 연결한다. 한 식사에는 여러 관찰을 연결할 수 있다.
- 새 시점의 관찰은 새 기록으로 추가한다. 기존 관찰의 오입력은 수정 기능으로 고친다.
- 연결된 식사보다 이른 관찰 시각은 허용하지 않으며, 시각 수정 또는 연결 해제를 안내한다.

**완료 기준:** 졸림만 입력해 저장할 수 있다. 동일 식사에 두 시점의 관찰을 추가하면 둘 다 유지된다. 식사 연결 없는 배변 기록도 저장된다.

### FR-03. 영역별 입력

아래 척도는 빠른 입력을 위한 제품 제안이며 의료적 평가 척도가 아니다.

| 영역 | 기본 입력 제안 | 선택 상세 |
| --- | --- | --- |
| 소화·속 편안함 | 편안함 / 보통 / 불편함 / 모르겠음 | 더부룩함·속쓰림·복부 불편감·가스·메스꺼움 복수 선택, 항목별 약함·중간·심함, 메모 |
| 졸림 | 없음 / 약간 / 많이 / 모르겠음 | 메모 |
| 에너지 | 활력 있음 / 평소와 비슷함 / 기운 없음 / 모르겠음 | 메모 |
| 배변 | 배변 사건의 시각, 편안함 / 보통 / 불편함 / 모르겠음 | 변의 상태: 단단함·보통·묽음·모르겠음, 메모 |

- 관찰 시각은 ‘상태를 느낀 시각’을 뜻한다. 배변은 해당 사건의 시각을 사용하며, 다른 시점의 상태는 별도 관찰로 기록한다.
- 관찰하지 않은 영역은 미기록으로 둔다. ‘모르겠음’은 사용자가 명시적으로 선택한 값이다.
- ‘보통’, ‘평소와 비슷함’, ‘없음’은 실제 응답이며 빈값으로 취급하지 않는다.
- 소화·졸림·에너지를 서로 추론하거나 자동 완성하지 않는다. 배변 기록이 없는 날을 변비나 정상으로 해석하지 않는다.
- 소화 상세 증상을 선택했다면 기본 응답도 받는다. ‘편안함’과 불편 증상을 함께 고르면 확인 안내를 제공하고 사용자가 내용을 고치거나 그대로 남길 수 있게 한다.

**완료 기준:** ‘속 편안함’과 ‘많이 졸림’이 한 관찰에 함께 저장된다. 작성하지 않은 에너지는 미기록으로 남는다. 모르겠음과 미기록을 화면·데이터에서 구분한다.

### FR-04. 하루 타임라인

- 날짜별로 식사와 몸 상태를 사건 시각순으로 보여준다. 같은 시각이면 생성 순서를 사용한다.
- 각 기록에서 상세 보기, 수정, 삭제를 제공한다.
- 연결된 관찰에는 식사 이름·먹은 시각·식후 경과 시간을 표시한다. 연결되지 않은 관찰에는 식사 연결 없음을 표시한다.
- 기록 없는 날에는 식사 또는 몸 상태를 추가할 수 있는 빈 화면을 제공한다.

**완료 기준:** 전날 식사와 다음 날 관찰도 연결을 유지하며, 관찰은 관찰한 날짜에 표시된다. 날짜 이동으로 과거 기록을 확인할 수 있다.

### FR-05. 음식 사전과 요약

- 음식 이름 검색, 음식 목록, 음식 상세를 제공한다.
- 상세에서 해당 음식을 포함한 식사 목록, 함께 먹은 음식, 연결된 관찰과 원래 메모를 볼 수 있다.
- 기간 필터는 전체·최근 7일·최근 30일을 제안하며, 식사 시각을 기준으로 포함할 식사를 정한다. 해당 식사에 연결된 관찰은 날짜가 넘어가도 포함한다.
- 영역별 응답 분포와 관찰 수를 보여준다. 종합 건강 점수나 자동 좋음·나쁨 순위는 만들지 않는다.
- 여러 음식이 포함된 식사의 관찰에는 ‘이 음식을 포함한 식사에서 남긴 기록’임을 명시한다.

**완료 기준:** 사용자는 요약에서 원래 식사와 관찰을 열 수 있다. 식사에 연결되지 않은 기록은 음식별 집계에 포함되지 않는다. 필터 변경 시 표본 수와 분포가 함께 바뀐다.

### FR-06. 수정·삭제와 데이터 일관성

- 식사와 관찰의 내용·시각·연결을 수정할 수 있다. 변경하면 타임라인과 요약에 반영한다.
- 식사를 삭제하기 전 연결된 관찰 수를 안내한다. 식사만 삭제하고 관찰은 독립 기록으로 보존한다.
- 관찰 삭제 시 해당 관찰만 제거하며 식사는 유지한다. 삭제 전 확인을 받는다.
- 식사 시각 수정으로 연결된 관찰이 식사보다 앞서면 저장을 막고 시각 또는 연결 수정을 안내한다.
- 기존 음식 항목의 전체 이름 변경·병합·삭제는 첫 버전에서 보류한다. 식사에 잘못 선택한 음식은 식사 수정으로 교체한다.

**완료 기준:** 식사 삭제 후 관찰은 타임라인에 남고 음식별 집계에서 빠진다. 관찰 수정·삭제 후 요약에 이전 값이 남지 않는다.

## 5. 집계와 해석 규칙

| 항목 | 규칙 |
| --- | --- |
| 음식별 식사 수 | 해당 음식이 포함된 고유 식사 수. 한 식사에 같은 음식이 반복되어도 한 번 계산 |
| 영역별 관찰 수 | 해당 영역에 명시적 응답이 있는 관찰 수. 같은 식사의 여러 시점은 각각 계산 |
| 관찰한 식사 수 | 해당 영역의 응답이 한 번 이상 있는 고유 식사 수 |
| 응답 분포 | 각 기본 응답의 건수 표시. 모르겠음도 별도 건수로 표시하고 미기록은 응답 분포에서 제외 |
| 미기록 | 관련 식사 중 해당 영역의 관찰이 한 번도 없는 식사 수로 표시 |
| 복수 음식 | 한 관찰이 각 음식 상세에서 나타날 수 있으나, 음식별 수치를 합산해 전체 관찰 수로 사용하지 않음 |
| 부족한 관찰 | 표본 수를 항상 표시. 관찰이 없으면 ‘아직 반응 기록이 없어요’ 표시. 적합성 결론이나 임의의 신뢰도 등급 없음 |
| 독립 관찰 | 하루 타임라인에 표시. 사용자가 식사에 연결하기 전에는 음식에 자동 귀속하지 않음 |

반응이 여러 번 기록된 한 식사가 요약에서 차지하는 비중을 알 수 있도록 **관찰 수와 관찰한 식사 수를 함께** 표시한다. 배변 요약은 기록된 배변 사건의 상태를 보여주며 음식의 효과로 표현하지 않는다.

## 6. 주요 화면과 이동

| 화면 | 주요 내용 | 주요 동작 |
| --- | --- | --- |
| 오늘 / 하루 타임라인 | 날짜 선택, 식사와 관찰 카드 | 식사 추가, 몸 상태 추가, 상세 열기 |
| 식사 작성·수정 | 음식 선택, 먹은 시각, 양, 메모 | 저장, 취소 |
| 몸 상태 작성·수정 | 관찰 시각, 선택적 식사 연결, 영역별 입력 | 저장, 취소 |
| 식사 상세 | 음식·시각·메모와 연결된 관찰 | 반응 추가, 수정, 삭제 |
| 내 음식 사전 | 이름 검색, 음식 목록 | 음식 상세 열기 |
| 음식 상세 | 기간, 영역별 집계, 관련 식사·관찰 | 원래 기록 열기 |

저장 실패 시 입력값을 유지하고 재시도를 제공한다. 저장 중 중복 제출을 막으며, 완료되기 전에는 저장 성공으로 표시하지 않는다.

## 7. 논리 데이터 구조

구현 기술과 무관한 논리 모델이며 실제 저장 기술은 미정이다.

| 개체 | 주요 필드와 관계 |
| --- | --- |
| 음식 | id, 이름, 생성·수정 시각 |
| 식사 | id, 먹은 시각, 기록 시간대, 메모, 생성·수정 시각 |
| 식사 음식 | 식사 id, 음식 id, 선택적인 양 메모 |
| 몸 상태 관찰 | id, 관찰 시각, 기록 시간대, 식사 id(선택), 메모, 생성·수정 시각 |
| 영역별 응답 | 관찰 id, 영역, 기본 응답, 선택적인 상세. 한 관찰에서 영역당 한 응답 |

음식↔식사는 다대다, 식사↔관찰은 일대다이며 관찰은 식사 없이 존재할 수 있다. 서버 저장을 선택하면 모든 개인 데이터에 소유자를 연결하고 소유자 범위 내에서만 조회·수정한다. 날짜 구분과 경과 시간은 기록된 시각·시간대를 기준으로 일관되게 계산한다.

## 8. 품질·개인정보 요구사항

- 네 영역을 모두 채우지 않아도 핵심 동작을 완료할 수 있어야 한다.
- 작은 휴대폰 화면에서도 입력·조회가 가능하고, 필드 이름·선택 상태·오류 원인을 텍스트로 이해할 수 있어야 한다. 색상만으로 반응을 구분하지 않는다.
- 새로고침·재실행 후 저장된 기록을 다시 볼 수 있어야 한다. 저장 방식에 따른 보존 범위는 실제 사용 전에 명시한다.
- 개인 기록은 기본 비공개이며, 공개 링크나 검색 노출을 제공하지 않는다.
- 서버 저장 시 사용자 간 기록 접근을 차단한다. 기기 저장 시 저장 위치와 삭제·기기 변경 시 보존 범위를 안내한다.
- 실제 식사·몸 상태·사진은 공개 GitHub 저장소, 테스트 자료, 분석 이벤트, 오류 로그에 넣지 않는다. 검증에는 가상 기록을 사용한다.
- 알림은 도입 시 사용자가 켜고 끌 수 있게 하며, 잠금 화면 문구는 구체적인 몸 상태를 노출하지 않는 방식으로 설계한다.

## 9. 검증 계획과 출시 완료 기준

### 사용성 검증 목표 제안

- 음식 선택을 포함한 간단한 식사 기록을 1분 이내에 완료한다.
- 한 영역의 몸 상태 기록을 30초 이내에 완료한다.
- 2주간 사용 후, 사용자가 기록을 근거로 자신의 경험을 설명하고 원래 기록을 다시 찾을 수 있다.
- 건강 개선 자체를 첫 버전의 성과 지표로 약속하지 않는다. 입력 지속성과 기록을 이해하는 데 도움이 되는지를 확인한다.

### 필수 검증 시나리오

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| AC-01 | 음식 두 개와 과거 시각으로 식사 저장 | 같은 식사에 두 음식이 보이고 올바른 날짜에 표시 |
| AC-02 | 소화·졸림만 응답 | 두 영역 저장, 에너지·배변은 미기록 유지 |
| AC-03 | 같은 식사에 다른 시각의 관찰 추가 | 두 관찰 유지, 관찰 수 2·관찰한 식사 수 1 |
| AC-04 | 식사 연결 없이 배변 기록 | 타임라인 표시, 음식별 요약에서는 제외 |
| AC-05 | 모르겠음과 없음·보통 입력 | 명시적 응답으로 보존, 미기록과 구분 |
| AC-06 | 여러 음식이 포함된 식사 요약 | 식사 전체 반응이라는 맥락과 원문 접근 제공 |
| AC-07 | 관찰 수정·삭제 및 식사 삭제 | 분포 갱신, 식사 삭제 시 관찰 연결 해제·보존 |
| AC-08 | 자정 전 식사에 다음 날 관찰 연결 | 날짜와 경과 시간 정확, 연결 유지 |
| AC-09 | 저장 실패 또는 중복 클릭 | 입력 유지, 실패 안내, 중복 기록 방지 |
| AC-10 | 기록 없음·관찰 없음·기간 필터 변경 | 적절한 빈 화면, 표본 수와 분포 일치 |
| AC-11 | 저장 후 재실행 및 개인 데이터 접근 | 저장 기록 유지, 선택한 저장 방식의 접근 제한 충족 |

출시 전 필수 기능과 위 시나리오를 검증하고, 플랫폼·저장 방식·첫 버전 알림 포함 여부를 확정한다.
